# Off-Pi race video review

The Pi remains the source of truth for the recording, race markers, racer roster, lap ledger, and championship. A stronger computer fetches a saved race video, analyzes sequences around directed finish-line crossings, and sends a **proposal** back. A proposal never changes laps or standings by itself. The browser compares recorded and proposed totals, and **Apply complete proposal** atomically backs up and replaces laps. Finished races are rescored in the same database transaction.

The exchange uses race-scoped endpoints:

| Endpoint | Purpose |
| --- | --- |
| `POST /api/quick/review/{race_id}/request` | Queue a paused or finished replay for compute review |
| `GET /api/quick/review/jobs` | Let workers discover requested races |
| `GET /api/quick/review/{race_id}/manifest` | Return video hash, markers, gate, roster, lap target, and ledger hash |
| `GET /api/quick/review/{race_id}/video` | Stream the original MP4 for offline analysis |
| `POST /api/quick/review/{race_id}/proposal` | Submit attributed crossings with confidence and surrounding-frame timestamps |
| `POST /api/quick/review/{race_id}/apply` | Apply a complete proposal after viewing its summary |

The server rejects proposals for a different video, unknown racer, out-of-range timestamp, implausibly short lap, or too many laps. A proposal stays incomplete if any crossing is unassigned, any proposed identity is below 0.9 confidence, or any entered racer has fewer than two crossings. The first crossing starts that car's timing; each later crossing completes one lap. The server saves the original laps and results under `review_backup:{race_id}:{proposal_id}` before replacement. A changed ledger invalidates an older proposal.

On Windows, set `J5_PI_URL`, `J5_NEMOCLAW_SANDBOX`, and `J5_OPENSHELL_PATH` in your local environment, then use `scripts/run_nemoclaw_review.ps1 -RaceId <race-id> -Limit 20` from PowerShell. Alternatively, pass `-Pi`, `-Sandbox`, and `-OpenShell` directly. Keep real Pi addresses, sandbox names, and credentials out of the repository. The script downloads the video into `%USERPROFILE%\j5-reviews`, detects candidate crossings, builds seven-frame temporal strips, uploads those strips to the NemoClaw sandbox, runs the NVIDIA vision model, downloads its resumable classifications, and submits the proposal to the Pi. Run the same command again to review the next batch; labels already returned are kept on the host. The NVIDIA key remains in the sandbox. The Pi never receives it. For another compute provider, `scripts/offboard_review.py` accepts `NVIDIA_API_KEY` locally and can run with `--watch --submit` to process queued races; pass `--pi` or set `J5_PI_URL`.

For a connected Windows computer to respond to the browser's **Request computer analysis** button, run `scripts/watch_nemoclaw_reviews.ps1` with `-Pi`, `-Sandbox`, `-OpenShell`, and `-NemoClaw` pointing to your local installation. It polls queued jobs while running. Its log and resumable classifications stay under `-OutputDir` (by default `%USERPROFILE%\j5-reviews`). If the first ten reviewed crossings yield no identifiable car, it returns an incomplete proposal rather than spending more inference calls or inventing laps. The button queues work; it cannot wake a computer that is off or start NemoClaw on the Pi.

The model is a visual assistant, not proof of identity. On the current 640x360 GoPro replay, a seven-frame test showed a moving car, but the model reversed its direction and could not name the racer. In the first automated batch it missed a visible car altogether. The worker therefore checks direction through computer vision, checks plausible lap spacing, and leaves unclear identities unassigned. An incomplete proposal cannot overwrite the ledger. Better footage, multiple views, or validated per-car reference imagery may be needed before this recording can produce four dependable lap totals. [NVIDIA's model page](https://build.nvidia.com/nvidia/nemotron-3.5-super-vl-120b-a12b) documents the hosted vision endpoint used by the optional worker.

For a repeatable local crossing audit, `scripts/replay_track_preview.py` takes a downloaded video and its race manifest, verifies the video hash, learns the background, and follows moving objects across a leftward saved finish gate. Run it from a private working directory with `--video race.mp4 --manifest manifest.json --output preview.json`. Its JSON contains per-frame track points and motion evidence, but no racer identities, images, or official laps. The script does not contact the Pi. At 640x360, its motion size limit includes the larger red-car blur that an earlier pass missed, while its speed and distance check marks hands, hair, and stationary motion as weak evidence. These are heuristic scores, not calibrated probabilities. Inspect and merge an existing browser preview before uploading: `POST /api/quick/review/{race_id}/tracks` replaces the entire provisional preview, including human assignments. Keep the video, manifest, and output JSON outside the public repository.
